# Deployment

> Describes [`render.yaml`](../render.yaml) as committed, and what is and is not recorded about the live deployment. The live demonstration is at <https://landfall-web-t5rw.onrender.com>; it runs the **PayPal Sandbox**. How Render is wired to GitHub (auto-deploy, branch) is configured in the Render dashboard and is not recorded in this repository.

## What the blueprint creates

| Item | Setting |
|---|---|
| Web service `landfall-web` | Node 22, **free plan**; `buildCommand: pnpm install && pnpm db:push --force && pnpm build`; `startCommand: pnpm start` |
| Database `landfall-db` | Render PostgreSQL, **free plan**; `db:push --force` creates the schema on every build against it |
| No cron service | Render cron has no free tier. Webhooks and the "Refresh from PayPal" button keep statuses current; `pnpm cron:poll` can be run from any external scheduler |

A free web service may sleep when idle, so the first request after a pause can be slow; this is a platform behaviour, not an application one.

## Environment

Set in the Render dashboard (`sync: false` in the blueprint means "you provide it"):

| Group | Variables |
|---|---|
| PayPal | `PAYPAL_ENV=sandbox`, `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET`, `PAYPAL_WEBHOOK_ID`, `NEXT_PUBLIC_PAYPAL_CLIENT_ID`, `PAYPAL_LIPP_REDIRECT` |
| AI | `GROQ_API_KEY`; model names are set in the blueprint |
| Sessions and crons | `SESSION_SECRET` and `CRON_SECRET` (generated by Render) |
| Passkeys | `WEBAUTHN_RP_ID` (host, no scheme) and `WEBAUTHN_ORIGIN` (full origin), "set after the first deploy" |
| Demo and caps | `JUDGE_MODE_ENABLED=true`, `DEMO_APPROVAL_PIN`, `LIVE_PAYOUT_MAX_ITEM_CENTS`, `LIVE_PAYOUT_MAX_TOTAL_CENTS`, `SANDBOX_RECEIVERS` |
| AG | `NEXT_PUBLIC_AG_GRID_LICENSE`, `NEXT_PUBLIC_AG_STUDIO_LICENSE` |
| Other | `PAYOUT_REFRESH_ENABLED`, `NWS_USER_AGENT`, `APP_URL` |

**Not in the blueprint but needed for any real data:** `PII_ENCRYPTION_KEY` (without it a source-code fallback key is used), `DEMO_KEY_DISABLED=true`, `EMERGENCY_STOP` available as a kill switch, and `JUDGE_MODE_ENABLED=false` once real authentication exists. See [SECURITY.md](../SECURITY.md).

## First deploy checklist

1. Create the blueprint; supply the `sync: false` values.
2. Note the service URL; set `APP_URL`, `WEBAUTHN_RP_ID`, `WEBAUTHN_ORIGIN`.
3. Register the webhook: `pnpm exec tsx scripts/register-webhook.ts <url> --apply` (dry-run first), then set the printed id as `PAYPAL_WEBHOOK_ID` (the receiver answers 503 to every event without it).
4. Open `/judges` and `/console/war-room`; confirm the Smart Buttons render on `/#give`.
5. If AG Grid shows an evaluation notice, the licence variable is missing or invalid.

## Rolling back and recovering

* **Application**: redeploy a previous commit from Render.
* **Database**: there are **no migrations and no documented backup or restore** ([LIMITATIONS.md](LIMITATIONS.md)). `db:push --force` on a database with data can drop or alter columns; do not run it against data you need without a plan.
* **PayPal is the source of truth for payments**: after a restore, run "Refresh from PayPal" to re-read the batches Landfall recorded.

## What this deployment is not

A hardened production environment: single instance, in-memory rate limiting, free-tier database, demonstration sign-in. Those are the first things to change ([ROADMAP.md](ROADMAP.md)).
